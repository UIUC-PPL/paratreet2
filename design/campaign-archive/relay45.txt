1.  THE DESIGN, and why it is arranged this way.
    Five configurations x 3 reps, INTERLEAVED rep-major so drift over the job
    hits every configuration equally.  Running three of one and then three of
    the next would confound drift with configuration.
    One WARM-UP arm first, discarded: the first arm of every job pays the cold
    read of the 76 GB input, which is the largest single confound in a rep
    study (27 s srun wall against 16-19 s).
    The two binaries link against DIFFERENT runtimes, so LD_LIBRARY_PATH is
    set PER ARM and every arm re-gates on the resolved libraries.  Getting
    that wrong is relay16 trap 6a and would silently run one stack while
    claiming the other.

3.  Q4, THE NOISE QUESTION -- and it needs the drift correction to read.
    Raw, the answer looks mixed:

      stack    fixed range        unfixed range      ratio
      merged    30.9 ms (0.9%)    197.8 ms (4.3%)    6.4x
      latest   210.6 ms (6.0%)    284.6 ms (6.0%)    1.4x

    BUT REP 3 WAS GLOBALLY SLOW.  Four of the five configurations hit their
    maximum in rep 3 -- merged-fix, latest-fix, latest-nofix and latest-p14.
    That is an external drift late in the job, and it is exactly what the
    interleaving was there to expose.  Excluding rep 3 as drifted:

      stack    fixed range        unfixed range      ratio
      merged    27.2 ms (0.8%)    196.5 ms (4.3%)    7.2x
      latest    10.2 ms (0.3%)    100.1 ms (2.2%)    9.8x

    Read that way BOTH stacks agree: THE FIXED CONFIGURATION IS 7-10x MORE
    REPRODUCIBLE THAN THE UNFIXED ONE.  That is consistent with the mechanism
    -- what the fix removes is a stochastic preemption, so removing it should
    cut variance as well as the mean.

    I AM FLAGGING THE POST-HOC EXCLUSION RATHER THAN HIDING IT.  Dropping rep
    3 is defensible only because the drift is visible across four independent
    configurations, not because it helps the conclusion; the raw table above
    is the primary result and the merged stack shows the effect (6.4x) without
    any exclusion at all.  A cleaner design would run more reps and test for
    drift formally.
