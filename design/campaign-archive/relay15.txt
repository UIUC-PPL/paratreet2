10. WHY I READ THIS AS NODE PLACEMENT, NOT THE CLEANUP.  Every one of these
    counters is a function of which PE claimed which piece, and the claim
    pool is a live race.  Edge counts vary run to run INSIDE one job by
    about the size of the between-job difference (relay13 spread 3,054
    edges over 7 runs; relay15 2,779 over 4).  The pattern is the tell:
    within a job these numbers are near-constant, between jobs they shift
    as a block.  phaseA_skew:within makes it explicit, now at three values
    on three jobs:

    RELAY15 SITS BETWEEN THE TWO EARLIER JOBS, so the ordering does not
    track the code at all.  Relay13 caveat 25 already flagged this figure
    as tracking the allocation or the claim race; this is the third point
